This module computes discrete logarithms in cyclic subgroups of
$(\Z/m\Z)^\times$ for word-size moduli $m$, mostly primes and prime
powers: given $a$ of order $n$ and $b \in \langle a \rangle$, it finds
$x \in [0, n)$ with $a^x \equiv b \pmod m$. It was written for
Dirichlet characters (`dirichlet`, `acb_dirichlet`), where many
logarithms are taken in the same group, so its central object is a
precomputation, `dlog_precomp_t`, built for a given base and an
expected number of queries: the choice of method (complete table,
baby-step giant-step, Pohlig–Hellman decomposition, $p$-adic
logarithm) and the amount of stored data depend on the structure of the
group and on that number. The module also computes the logarithms of all
integers $1, \ldots, N-1$ at once, by enumeration or by sieving.

Little effort has been made for a single logarithm in a large group of
prime order. For one-off logarithms modulo a prime with smooth $p - 1$,
see also `nmod_discrete_log_pohlig_hellman`
([](algorithms/number-theory/discrete-log)). [](dlog/precomp) explains how to set up a precomputation, and the
algorithms are described in
[](algorithms/number-theory/discrete-log-tables).

## Conventions {#conventions}

Logarithms are returned as `ulong` values in $[0, n)$, where $n$ is the
order of the base. The base must have exactly the order passed to the
functions, and the moduli must fit in a word; none of this is checked.
The result for an argument $b$ outside the subgroup generated by the base
is not specified (some methods throw, others return a wrong value).

::: macro
DLOG_NONE
DLOG_NOT_FOUND

The value `UWORD_MAX`, used in vectors of logarithms for the entries
whose logarithm does not exist (integers not coprime to the modulus).
:::

## Single logarithms {#single}

::: function
ulong dlog_once(ulong b, ulong a, const nmod_t mod, ulong n)

Returns $x$ with $a^x \equiv b$ modulo `mod.n`, where $a$ has order $n$:
by enumerating the powers of $a$ for $n < 50$ (throwing if $b$ is not
found), and otherwise with a precomputation for one query
(`dlog_precomp_n_init` with `num` $= 1$), which is cleared afterwards.
:::

## Precomputed logarithms {#precomp}

::: type
dlog_precomp_struct
dlog_precomp_t

Precomputed data for logarithms to a fixed base: the method (`type`), an
estimate of the cost of one logarithm (`cost`, in multiplications), and
the data of the method. A `dlog_precomp_t` is an array of length one of
`dlog_precomp_struct`.
:::

::: function
void dlog_precomp_n_init(dlog_precomp_t pre, ulong a, ulong mod, ulong n, ulong num)

Initialises `pre` for about `num` logarithms to the base $a$ of order $n$
modulo `mod`, with no further information on $n$. If $n$ is an odd prime
the function calls `dlog_precomp_p_init`; otherwise it uses a complete
table for $n < 50$, baby-step giant-step for $n < 500$, and the
Pohlig–Hellman decomposition (`dlog_crt_init`) above.
:::

::: function
void dlog_precomp_p_init(dlog_precomp_t pre, ulong a, ulong mod, ulong p, ulong num)

As `dlog_precomp_n_init` for a base of prime order $p$: a complete table
for $p < 50$, otherwise baby-step giant-step with a table of
`dlog_bsgs_size(p, num)` powers.
:::

::: function
void dlog_precomp_pe_init(dlog_precomp_t pre, ulong a, ulong mod, ulong p, ulong e, ulong pe, ulong num)

As `dlog_precomp_n_init` for a base of prime power order $\mathit{pe} =
p^e$: a complete table for $p^e < 50$, `dlog_precomp_p_init` for $e =
1$, and otherwise the base-$p$ digit decomposition (`dlog_power_init`).
:::

::: function
void dlog_precomp_modpe_init(dlog_precomp_t pre, ulong a, ulong p, ulong e, ulong pe, ulong num)

Initialises `pre` for logarithms to the base $a$ modulo $\mathit{pe} =
p^e$, where $a$ generates $(\Z/p^e\Z)^\times$ (for odd $p$), or, for $p =
2$ and $e \ge 3$, $a = 5$ generates the subgroup of elements congruent to
1 modulo 4. Uses a complete table for $p^e < 50$, the reduction to a
logarithm modulo $p$ and a $p$-adic logarithm (`dlog_modpe_init`) for $e
\ge 2$, and `dlog_precomp_n_init` modulo $p$ for $e = 1$.
:::

::: function
void dlog_precomp_small_init(dlog_precomp_t pre, ulong a, ulong mod, ulong n, ulong num)

Initialises `pre` for a group of small order $n$: the trivial method for
$n \le 3$, a complete table indexed by the residues if $\mathit{mod} <
50$, and otherwise a baby-step giant-step table containing all $n$
powers (so that a logarithm is one binary search).
:::

::: function
ulong dlog_precomp(const dlog_precomp_t pre, ulong b)

Returns the logarithm of $b$ (reduced modulo the modulus) to the base of
`pre`.
:::

::: function
void dlog_precomp_clear(dlog_precomp_t pre)

Frees the memory used by `pre`. Does nothing if `pre` is `NULL`.
:::

## Vectors of logarithms {#vectors}

These functions compute, for all $0 \le k < \mathit{nv}$, the value
$v_a \log_a(k) \bmod \mathit{order}$, where $\log_a(k)$ is the logarithm
of $k \bmod m$ to a base $a$ of order $n_a$ (`na`) generating
$(\Z/m\Z)^\times$ (so $m$ is a prime power or twice one). The modulus
`order` must divide $v_a n_a$, so that the result is well defined; with
$v_a = 1$ and $\mathit{order} = n_a$ these are the plain logarithms. Entries for $k$ not coprime to $m$ are `DLOG_NONE`.
This is the form needed for the exponents of Dirichlet characters.

::: function
void dlog_vec(ulong * v, ulong nv, ulong a, ulong va, nmod_t mod, ulong na, nmod_t order)
void dlog_vec_add(ulong * v, ulong nv, ulong a, ulong va, nmod_t mod, ulong na, nmod_t order)

Set $v[k]$ to $v_a \log_a(k) \bmod \mathit{order}$, or (the `add`
version) add it to $v[k]$ modulo `order` for every $k$ with $v[k] \ne$
`DLOG_NONE`. They do nothing if $v_a = 0$. Both use `loop` if $6 n_a <
\mathit{nv}$ and `sieve` otherwise.
:::

::: function
void dlog_vec_loop(ulong * v, ulong nv, ulong a, ulong va, nmod_t mod, ulong na, nmod_t order)
void dlog_vec_loop_add(ulong * v, ulong nv, ulong a, ulong va, nmod_t mod, ulong na, nmod_t order)

As `dlog_vec` and `dlog_vec_add`, by enumerating the $n_a$ powers of $a$
and copying the values to the entries $k \ge m$ by periodicity. Costs
$O(n_a + \mathit{nv})$ and needs no discrete logarithm.
:::

::: function
void dlog_vec_sieve(ulong * v, ulong nv, ulong a, ulong va, nmod_t mod, ulong na, nmod_t order)
void dlog_vec_sieve_add(ulong * v, ulong nv, ulong a, ulong va, nmod_t mod, ulong na, nmod_t order)

As `dlog_vec` and `dlog_vec_add`, by computing the logarithms of the
primes $p < \min(\mathit{nv}, m)$ and extending them to all $k$ by
complete multiplicativity. The logarithms of the primes are computed
with a precomputation for 50 queries, except that for primes large
enough a relation with smaller numbers is searched first
(`dlog_vec_pindex_factorgcd`). The full index calculus method is not
implemented.
:::

::: function
void dlog_vec_sieve_precomp(ulong * v, ulong nv, dlog_precomp_t pre, ulong a, ulong va, nmod_t mod, ulong na, nmod_t order)
void dlog_vec_sieve_add_precomp(ulong * v, ulong nv, dlog_precomp_t pre, ulong a, ulong va, nmod_t mod, ulong na, nmod_t order)
void dlog_vec_add_precomp(ulong * v, ulong nv, dlog_precomp_t pre, ulong a, ulong va, nmod_t mod, ulong na, nmod_t order)

As `dlog_vec_sieve`, `dlog_vec_sieve_add` and `dlog_vec_add`, with the
logarithms of the primes taken from an existing precomputation `pre` for
the base $a$.
:::

::: function
void dlog_vec_eratos(ulong * v, ulong nv, ulong a, ulong va, nmod_t mod, ulong na, nmod_t order)
void dlog_vec_eratos_add(ulong * v, ulong nv, ulong a, ulong va, nmod_t mod, ulong na, nmod_t order)

As `dlog_vec` and `dlog_vec_add`, by computing the logarithm of every
prime below $\min(\mathit{nv}, m)$ with a precomputation and adding it
to all multiples of its powers, as in the sieve of Eratosthenes. The
`add` version assumes that the entries not coprime to $m$ are already
`DLOG_NONE`.
:::

::: function
void dlog_vec_fill(ulong * v, ulong nv, ulong x)

Sets $v[k] = x$ for $0 \le k < \mathit{nv}$.
:::

::: function
void dlog_vec_set_not_found(ulong * v, ulong nv, nmod_t mod)

Sets $v[k]$ to `DLOG_NONE` for the $0 < k < \mathit{nv}$ divisible by a
prime factor of the modulus.
:::

::: function
ulong dlog_vec_pindex_factorgcd(ulong * v, ulong nv, ulong p, nmod_t mod, ulong a, ulong na, ulong loga, ulong logm1, nmod_t order, int maxtry)

Tries to find the logarithm of the prime $p$ from the logarithms already
stored in $v$: for $i = 1, 2, \ldots$ up to `maxtry`, writes $p a^i \equiv
\pm r/u \pmod m$ with $r, u$ about $\sqrt m$ by a partial extended
Euclidean algorithm, and if $r$ and $u$ factor over the entries of $v$
already known (after removing primes below $p/4$), returns
$\log r - \log u - i \log a$ (adjusted by `logm1`, the logarithm of
$-1$). Here `loga` is the value to use for $\log a$. Returns
`DLOG_NOT_FOUND` if no relation is found.
:::

## Methods {#methods}

Each method has a structure, an `init` function that returns an estimate
of the cost of one logarithm, the logarithm function and a `clear`
function. They are used through `dlog_precomp_t`, but can also be called
directly. In all of them $a$ is the base and $b$ the argument.

### Complete table {#table}

::: type
dlog_table_struct
dlog_table_t

A table of size `mod` giving the logarithm of every residue (for small
moduli only).
:::

::: function
ulong dlog_table_init(dlog_table_t t, ulong a, ulong mod)
void dlog_table_clear(dlog_table_t t)
ulong dlog_table(const dlog_table_t t, ulong b)

Build the table of the logarithms of the powers of $a$ modulo `mod` (an
array of `mod` words; $a$ must be invertible, which is not checked), free
it, and look up $\log_a(b)$. The cost estimate is 1.
:::

### Orders 2 and 3 {#order23}

::: type
dlog_order23_t

The base $a$ of a group of order at most 3.
:::

::: function
ulong dlog_order23_init(dlog_order23_t t, ulong a)
void dlog_order23_clear(dlog_order23_t t)
ulong dlog_order23(const dlog_order23_t t, ulong b)

Store $a$, do nothing, and return 0 if $b = 1$, 1 if $b = a$, and 2
otherwise. The cost estimate is 0.
:::

### Baby-step giant-step {#bsgs}

::: type
dlog_bsgs_struct
dlog_bsgs_t
apow_t

A sorted table of $m$ pairs $(k, a^k)$ (`apow_t`), for $0 \le k < m$,
together with $a^{-m}$ and the number of giant steps $\lfloor n/m
\rfloor + 1$.
:::

::: function
ulong dlog_bsgs_init(dlog_bsgs_t t, ulong a, ulong mod, ulong n, ulong m)

Initialises $t$ with the $m$ baby steps $a^0, \ldots, a^{m-1}$ (or $n$ if
$m > n$), sorted by value, for a base of order $n$. Returns the number of
giant steps $\lfloor n/m \rfloor + 1$, the worst-case cost of one
logarithm. For $k$ logarithms, $m \approx \sqrt{kn}$ minimises the total
cost.
:::

::: function
ulong dlog_bsgs_size(ulong n, ulong num)

Returns the table size used for `num` logarithms in a group of order
$n$: $(1 + \lfloor\sqrt n\rfloor)(1 + \lfloor\sqrt{\mathit{num}}\rfloor)$
if $2\,\mathit{num} < n$, and $n$ otherwise.
:::

::: function
void dlog_bsgs_clear(dlog_bsgs_t t)
ulong dlog_bsgs(const dlog_bsgs_t t, ulong b)

Free the table, and return $\log_a(b)$ by multiplying $b$ by $a^{-m}$ until
the product is found in the table (by binary search). Throws if $b$ is
not a power of $a$.
:::

::: function
int apow_cmp(const apow_t * x, const apow_t * y)

Comparison function of the pairs $(k, a^k)$ by the value $a^k$, for
`qsort` and `bsearch`.
:::

### Pohlig–Hellman decomposition {#crt}

::: type
dlog_crt_struct
dlog_crt_t

For a base $a$ of composite order $n = \prod p_i^{e_i}$: for each prime
power, the cofactor $n/p_i^{e_i}$, the CRT coefficient and a
precomputation in the subgroup of order $p_i^{e_i}$.
:::

::: function
ulong dlog_crt_init(dlog_crt_t t, ulong a, ulong mod, ulong n, ulong num)
void dlog_crt_clear(dlog_crt_t t)
ulong dlog_crt(const dlog_crt_t t, ulong b)

Initialise $t$ for `num` logarithms to the base $a$ of order $n$ modulo
`mod`, by factoring $n$ and initialising `dlog_precomp_pe_init` for
$a^{n/p^e}$ in each subgroup of prime power order (the returned cost is
the sum of their costs); free it; and return $\log_a(b)$, combining the
logarithms of $b^{n/p^e}$ by the Chinese remainder theorem.
:::

### Prime power order {#power}

::: type
dlog_power_struct
dlog_power_t

For a base $a$ of order $p^e$: the powers $a^{-p^k}$, $0 \le k < e$, and a
precomputation in the subgroup of order $p$, generated by $a^{p^{e-1}}$.
:::

::: function
ulong dlog_power_init(dlog_power_t t, ulong a, ulong mod, ulong p, ulong e, ulong num)
void dlog_power_clear(dlog_power_t t)
ulong dlog_power(const dlog_power_t t, ulong b)

Initialise $t$ for `num` logarithms to the base $a$ of order $p^e$ (the
subgroup precomputation is made for $e \cdot \mathit{num}$ logarithms and
the cost is $e$ times its cost); free it; and return $\log_a(b)$, found
one base-$p$ digit at a time, each digit a logarithm in the subgroup of
order $p$.
:::

### Prime power modulus {#modpe}

::: type
dlog_modpe_struct
dlog_modpe_t
dlog_1modpe_struct
dlog_1modpe_t

For the modulus $p^e$ with a generator $a$: a precomputation modulo $p$
(for odd $p$) and the data for logarithms in the subgroup $1 + p\Z$ of
elements congruent to 1 modulo $p$: $(1 + p)^{-1}$ and the inverse of the
logarithm of $a^{p-1}$ to the base $1 + p$.
:::

::: function
ulong dlog_modpe_init(dlog_modpe_t t, ulong a, ulong p, ulong e, ulong pe, ulong num)
void dlog_modpe_clear(dlog_modpe_t t)
ulong dlog_modpe(const dlog_modpe_t t, ulong b)

Initialise $t$ for `num` logarithms to the base $a$ modulo $\mathit{pe} =
p^e$; free it; and return $\log_a(b)$, combining the logarithm of $b \bmod
p$ modulo $p - 1$ with the logarithm of $b^{p-1}$ in $1 + p\Z$, which
determines $\log_a(b)$ modulo $p^{e-1}$. For $p = 2$ the base must be 5
(or a generator of the elements congruent to 1 modulo 4) and $b \equiv 1
\pmod 4$; this case uses `dlog_mod2e`.
:::

::: function
void dlog_1modpe_init(dlog_1modpe_t t, ulong a1, ulong p, ulong e, nmod_t pe)
ulong dlog_1modpe(const dlog_1modpe_t t, ulong b1, ulong p, ulong e, nmod_t pe)

For odd $p$ and $a_1 \equiv 1 \pmod p$ generating $1 + p\Z$ modulo
$p^e$, precompute the inverse of the logarithm of $a_1$ to the base $1 +
p$ (throws if $a_1 = 1$ and $e > 1$), and return the logarithm of $b_1
\equiv 1 \pmod p$ to the base $a_1$, modulo $p^{e-1}$.
:::

::: function
ulong dlog_1modpe_1modp(ulong b1, ulong p, ulong e, ulong inv1p, nmod_t pe)

Returns the logarithm $x \in [0, p^{e-1})$ of $b_1 \equiv 1 \pmod p$ to
the base $1 + p$ modulo $p^e$, given `inv1p` $= (1 + p)^{-1} \bmod p^e$,
determining one base-$p$ digit per step. Throws if $b_1 \not\equiv 1
\pmod p$.
:::

::: function
ulong dlog_mod2e_1mod4(ulong b1, ulong e, ulong inv5, nmod_t pe)
ulong dlog_mod2e(const dlog_modpe_t t, ulong b)

Return the logarithm of $b_1 \equiv 1 \pmod 4$ to the base 5 modulo
$2^e$, given `inv5` $= 5^{-1} \bmod 2^e$, determining one bit per step
(throws if $b_1 \not\equiv 1 \pmod 4$); and the logarithm for a
`dlog_modpe_t` with $p = 2$ (for $e = 2$, whether $b \equiv 3 \pmod 4$).
:::

### Pollard rho {#rho}

::: type
dlog_rho_struct
dlog_rho_t

The data for Pollard's rho method: the base, its order and the modulus.
:::

::: function
void dlog_rho_init(dlog_rho_t t, ulong a, ulong mod, ulong n)
void dlog_rho_clear(dlog_rho_t t)
ulong dlog_rho(const dlog_rho_t t, ulong b)

Initialise $t$ for the base $a$ of order $n$ modulo `mod`; do nothing;
and return $\log_a(b)$ with Pollard's rho method [@Pol1978], using a
random walk with 20 steps and Floyd's cycle detection, in expected time
$O(\sqrt n)$ and constant memory. For composite $n$ a relation that does
not determine the logarithm is completed recursively. This method is not
used by `dlog_precomp_t`.
:::
